# 力量训练心率分析模块设计（移除热量/时长，新增 Mechanical & Cardiovascular 双指标）

> 日期：2026-08-30
> 关联毕设选题：移动端/小程序开发类（泛前端方向）—— 设备传感器调用（蓝牙 HRS）、力量训练数据分析
> 关联项目：FitNote 健身记录小程序
> 状态：已批准（2026-08-30），准备实施
> 批准结果：5 项自检问题（含结束按钮一致性 / 同日多段训练 MVP 简化 / age=0 保护 / restingHR 三分支单测）已就地修复
> 替代：2026-08-28-心率热量推送-设计（本设计废止其中 §2 的"热量估算 / 时长累计 / 热量趋势"运行时使用，改为本设计的训练分析）

---

## 1. 概述与目标

在 FitNote 现有蓝牙心率接入能力（2026-08-28 设计，已实施）的基础上，**废弃基于心率的热量估算与累计时长统计**（废止 Keytel、MET 公式在训练页的运行时使用），取而代之建立一个**面向力量训练场景**、结合每组训练记录与 BLE 心率时序的分析模块。

### 核心原则（用户明确要求）

1. **不用 RIR（Rating of Perceived Repetitions-in-Reserve）** 做训练负荷模型。
2. **不捏造数据**：任一时间窗口内 BLE HR 采样不足时，该组（或该 session 汇总）的 HR 相关字段置 `null`，绝不插值或填充假值。
3. **双指标分离展示**：`Mechanical Training Load`（机械训练负荷 = Σ weight×reps）与 `Cardiovascular Training Load`（心血管训练负荷 = HRR 时间积分）**分开呈现、不合并**为所谓"真实训练负荷"单一值。
4. **显式估算来源**：凡是"估算值"（estimatedSetDuration、e1RM、restingHR）必须在数据结构与 UI 中明确标注其来源与性质，不能伪装成"实测"。
5. **动作级别 HR 长期画像（HR Profile）**：支持同一动作在不同重量、次数下的 HR response 长期聚合与可视化。

### 输出目标

每次训练（一天内一次训练）结束后，生成并持久化以下分析结果：
- 整次训练总览：`totalVolumeLoad` / `mechanicalLoad` / `cardiovascularLoad` / `averageHr` / `peakHr`
- 动作级统计：每个动作的平均 HR、Peak HR、平均 HR 增幅（ΔHR）
- 组级明细：每组 startHR / avgHR / peakHR / endHR / ΔHR + estimatedSetDuration 标注
- 长期聚合入口：跨多日训练聚合动作 HR Profile（按重量分桶）

### 4.3 TrainingAnalysis（核心输出结构）

```ts
TrainingAnalysis = {
  generatedAt: number,              // 本分析生成时间戳（用于 UI 显示"刚刚/xx 分钟前分析"）
  sessionStartTs: number,           // 训练会话开始 = 本次训练首个 entry.timestamp
  sessionEndTs: number|null,        // 训练会话结束 = 最后一个 entry.timestamp 或 HR 超时时
  status: 'in_progress'|'finalized',// 训练进行中 / 已结束固化

  session: {
    totalVolumeLoad: number,        // Σ(weight × reps) —— 所有 set
    mechanicalLoad: number,         // 语义别名：= totalVolumeLoad（UI 上明确展示）
    cardiovascularLoad: number|null,// HRR 梯形积分（分钟单位 × HRR 比例）；无足够数据 = null
    averageHr: number|null,         // 整次训练（sessionStartTs → sessionEndTs）所有有效 HR 的均值
    peakHr: number|null,            // 整次训练 max HR
    restingHrUsed:  { value: number, source: 'profile'|'estimated' },  // 明确来源
    maxHrUsed:      { value: number, source: 'formula' },              // 220 - age
  },

  setAnalyses: SetAnalysis[],       // 全局按 timestamp 排序（跨动作），长度 = 非占位 entry 总数
  actionAnalyses: { [actionName]: ActionAnalysis },
  hrProfiles?: {}                   // 单次训练留空 {}，独立完整页跨日聚合时填充
}

SetAnalysis = {
  actionName: string,
  setIndex: number,                 // 该动作内部第几组（1-based）
  timestamp: number,                // 拷贝自 entry.timestamp（为 null → 整组 HR 跳过）

  // 机械
  weight: number,                   // stages[0].weight（复合组取首段，复合 stage 则注释为 "首段重量"）
  reps: number,                     // sum(stages.reps)
  volumeLoad: number,               // weight × reps
  relativeIntensity: {
    value: number|null,             // weight / e1RM；e1RM 为 0 或 null → value: null
    e1RM: number|null,              // 估算值
    e1RMEstimated: boolean,         // = true（目前一律 Epley）
    source: 'epley'|null,           // 未来若接入用户 1RM 可扩展为 'user1RM'
  },

  // 时间（transition 与 estimated）
  transitionTimeSec: number|null,   // = ts[i+1] - ts[i]；最后一组 = null
  restDurationSec: number,          // 该动作类别对应的组间歇（heavy=180s, light=120s，同 settingsStore）
  estimatedSetDurationSec: number|null,  // = max(0, transitionTimeSec - restDurationSec)
  // ⚠ UI 必须显式标注为 "estimated set duration（估算法，非动作真实持续时间）"

  // HR 窗口分析
  hr: {
    analyzed: boolean,              // 核心标志：false → 下方所有数值为 null，不填假
    startHr: number|null,
    averageHr: number|null,
    peakHr: number|null,
    endHr: number|null,
    deltaHr: number|null,           // 定义 = peakHr - startHr（论文写作与 UI 说明时明确定义）
    sampleCount: number,            // 窗口内有效采样数
  }
}

ActionAnalysis = {
  actionName: string,
  setCount: number,
  totalVolume: number,
  averageHr: number|null,           // 仅汇总 analyzed=true 的 set 的 averageHr 的均值
  peakHr: number|null,              // 仅汇总 analyzed=true 的 set 的 peakHr 的 max

}
```

## 5. 算法模块设计：`utils/strengthTrainingAnalyzer.js`（全部纯函数）

模块内**不依赖 uni / Pinia / DOM**。所有依赖以参数形式传入（便于单测）。

### 5.1 工具函数

```ts
/** 基础 volume load */
calcVolumeLoad(weight: number, reps: number): number

/** Epley 公式估算 1RM（来源明确标注 estimated）
 *  e1RM = weight × (1 + reps / 30)
 */
estimateE1RMEpley(weight: number, reps: number): number

/** 相对强度，除 0 保护，无意义时返回 null */
calcRelativeIntensity(weight: number, oneRM: number|null): number|null

/** 心率储备比 HRR = clamp((HR - rHR) / (mHR - rHR), 0, 1) */
calcHRR(hr: number, restingHR: number, maxHR: number): number
```

### 5.2 HR 窗口提取 + 指标

```ts
/** 从 hrSamplesWithTs 中截取 [startTime, endTime] 区间内的采样。
 *  采样数 >= minSamples 时 analyzed=true，否则 false（绝不捏造数据）。
 *  返回 samples 始终为截取到的真实子集。
 */
extractHrWindow(
  hrSamplesWithTs: HrSampleWithTs[],
  startTime: number, endTime: number,
  minSamples = 3
): { samples: HrSampleWithTs[], sampleCount: number, analyzed: boolean }

/** 基于 extractHrWindow 结果计算组级 HR 指标。
 *  analyzed=false → 全量字段为 null。
 *  deltaHr 定义为 peakHr - startHr（与 §4.3 结构一致）。
 */
calcHrMetrics(window: ExtractHrWindowResult): HrAnalysis
```

### 5.3 HRR 时间积分（心血管负荷）

```ts
/** 心血管负荷（HRR·min）—— 对 sessionStartTs→sessionEndTs 范围的 HRR 做梯形积分。
 *  - 相邻两采样点 (ti, hi) 与 (ti+1, hi+1)：
 *      ΔtMin = (ti+1 - ti) / 60000
 *      avgHRR = (calcHRR(hi, r, m) + calcHRR(hi+1, r, m)) / 2
 *      area += ΔtMin * avgHRR
 *  - 单点情况 / 无数据 → 返回 null
 *  - restingHR >= maxHR 保护：返回 null 并 console.warn
 */
calcCardiovascularLoad(
  hrSamplesWithTs: HrSampleWithTs[],
  restingHR: number,
  maxHR: number,
  sessionStartTs: number,
  sessionEndTs: number|null
): number|null
```

### 5.4 restingHR 降级估算

```ts
/** 当 profile.restingHR 为 null 时调用：
 *  1. 取 sessionStartTs 之后前 windowSec（默认 60s）内的 HR 采样 → 最低值作为估算。
 *  2. 若数据不足（< 10 个采样），fallback：公式估算 restingHR ≈ round(maxHR × 0.4)（粗略经验），
 *     调用方将 source 标记为 'estimated'。
 */
estimateRestingHr(
  hrSamplesWithTs: HrSampleWithTs[],
  sessionStartTs: number,
  windowSec = 60,
  fallbackAge: number|null  // 若传 null，fallback 阶段跳过直接返回 null
): { value: number|null, source: 'window'|'formula'|'none' }
```

### 5.5 Epley 历史最佳读取（需要跨 dayData 查询，封装为 getter 入参）

```ts
/** 主 analyzeTrainingSession 不直接依赖 dayDataCacheStore，调用方传函数：
 *      historicalBestGetter(actionName) → {bestWeight, bestReps, bestDate}|null
 *  推荐上层实现见 §6，内部按"忽略当天，往前扫描所有已索引日期，取 w×(1+r/30) 最大"规则。
 */
type HistoricalBestGetter = (actionName: string) => {bestWeight:number, bestReps:number}|null
```

### 5.6 核心分析函数

```ts
/** 输入参数（均为 value，非 reactive）*/
interface AnalyzeTrainingSessionParams {
  entries: FlatEntry[]
    // FlatEntry = { actionName, setIndex, timestamp:number|null, weight, reps,
    //               volumeLoad, stages, bwMode, isPlaceholder:false }
    // 必须按 timestamp 升序排序（调用方负责排好）。
    // 占位 entry（isPlaceholder=true）必须过滤掉不传。
  hrSamplesWithTs: HrSampleWithTs[]
  restDurationSecByAction: (actionName: string) => number
      // 调用方根据动作类别返回：heavy(胸背腿)→settings.heavyTimerDuration
      //                                  light(肩手)→settings.lightTimerDuration
      //                                  abs→默认 lightTimerDuration
  profile: {
    gender: 'male'|'female'|null,
    age: number,
    weight: number,
    restingHR: number|null,
  }
  historicalBestGetter: HistoricalBestGetter
}

/** 返回 TrainingAnalysis 结构（§4.3）。
 *
 * 执行步骤：
 *  Step 1. 边界保护：若 entries.length === 0 → 返回空的 TrainingAnalysis（status=in_progress，数值 0 或 null）
 *  Step 2. sessionStartTs / sessionEndTs：
 *           startTs = 全部 entry 的最小 timestamp（跳过 null 的取最小值）
 *           endTs   = 全部 entry 的最大 timestamp；若为 0 或 NaN 兜底 Date.now()
 *  Step 3. restingHR / maxHR 决策：
 *           restingHR = profile.restingHR ?? estimateRestingHr(...).value，
 *           并写入 session.restingHrUsed；maxHR = 220 - age，写入 session.maxHrUsed
 *  Step 4. 按序遍历 entries：
 *           - 计算 transitionTimeSec （最后一组 = null）
 *           - 调用 restDurationSecByAction(actionName) 得 restDurationSec
 *           - estimatedSetDurationSec = max(0, transition - rest)，transition 为 null 则 estimated = null
 *           - 窗口定义：startWin = entry.timestamp
 *                       endWin   = estimatedSetDurationSec > 0
 *                                  ? startWin + estimatedSetDurationSec*1000
 *                                  : (i+1<len ? entries[i+1].timestamp : sessionEndTs)
 *           - extractHrWindow() → 若 analyzed=false → SetAnalysis.hr = {analyzed:false, ...null}
 *           - Epley：best = historicalBestGetter(actionName)
 *                    → e1RM = best ? estimateE1RMEpley(best.bestWeight, best.bestReps) : null
 *                    → relativeIntensity.value = e1RM ? weight/e1RM : null
 *  Step 5. 整次训练汇总：
 *           totalVolumeLoad = Σ set.volumeLoad，mechanicalLoad 同值；
 *           cardiovascularLoad = calcCardiovascularLoad(rHR, mHR, startTs, endTs)
 *           averageHr = session 窗口内所有 HR 的算术平均（长度 0 → null）
 *           peakHr    = session 窗口内 max（长度 0 → null）
 *  Step 6. actionAnalyses = 按 actionName 聚合 setAnalyses
 *  Step 7. 返回训练进行中 status='in_progress'（调用方根据会话结束判定另行 finalize 并持久化）
 */
analyzeTrainingSession(p: AnalyzeTrainingSessionParams): TrainingAnalysis
```

### 5.7 长期动作 HR Profile 聚合

```ts
/**
 * @param historicalAnalyses: Array<{date: string, analysis: TrainingAnalysis}>
 *        （一般是独立分析页从多日 dayData.trainingAnalysis 按时间筛选）
 * @param targetActionName: 例如 "杠铃卧推"
 *
 * 按重量分桶（桶边界：20, 30, 40, 50, 60, 70, 80, 100, 120 kg，>= 120 归为 "120+"）。
 * 只聚合 hr.analyzed=true 的 set。
 * 返回数组，可直接用于 canvas 绘图的数据源。
 */
aggregateActionHrProfiles(
  historicalAnalyses: Array<{date: string, analysis: TrainingAnalysis}>,
  targetActionName: string
): Array<{
  weightBucket: string,               // "20", "30", ..., "120+"
  weightBucketLower: number,          // 20, 30, ..., 120
  avgHr: number|null,
  peakHr: number|null,
  avgDeltaHr: number|null,
  sampleSets: number,                 // 聚合了多少组（用作可信度参考）
  points: Array<{date, weight, reps, avgHr, peakHr, deltaHr}>  // 每个点用于散点绘制
}>
```

## 6. 训练开始 / 结束判定（沿用现有机制）

**明确不引入新状态机**（用户在 Q3 补充说明中确认）。判定复用现有：

- **开始**：`day.vue.initHeartRate()` → BLE 首次成功回调 `onHeartRate(h)` 时，视为会话开始信号（不需要特殊动作，因为首组 entry.timestamp 会在用户点确认时写入，用作 sessionStartTs 锚点）。
- **暂停/继续**：复用现有 `hrTimer` 的 **10 秒无 HR 超时**逻辑 + `bleHeartRate.js` 重连机制（最多 3 次，间隔 1.5/3/5s）。该机制已能稳定应对手环短时丢信号。
- **结束（用于 trainingAnalysis.status 写入 finalized）**：两个条件任一满足即视为结束：
  1. 用户在 day.vue 离开页面（`beforeUnmount`）**且** `hrConnected === false` **且**距最后一次 entry 时间 > 5 分钟；或
  2. 用户在 TrainingAnalysisCard 底部点击「结束训练」按钮（见 §7.3 底部操作栏）。

结束后将 `trainingAnalysis.status = 'finalized'` 并写入 `sessionEndTs`。**本期 MVP 只支持单日一段训练**：若用户在同一 day 后续再追加新组，实现策略为重置 `trainingAnalysis.status = 'in_progress'` 并覆盖 sessionEndTs，整段分析以追加后的最终 entry 为尾；跨日训练分别写在各自 date 的 trainingAnalysis 中。多段训练（单日 session split）作为未来展望 item，不在本期范围。

## 8. 兼容性、回滚与风险控制

### 8.1 向下兼容

- **旧 dayData 读取**：所有修改点 `raw.xxx ?? [] / null`，缺失字段绝不抛异常。
- **旧 entry 无 timestamp**：normalizeEntry() 兜底填 `null` → 该组 transition/HR 分析跳过，机械侧照常，UI 显式告知。
- **旧 hrSamples（无 ts）**：TrainingAnalysisCard/独立页若 `hrSamplesWithTs.length === 0` 且 `hrSamples.length > 0`，显示灰色提示"本次训练为旧版格式，无法做逐组 HR 分析"。

### 8.2 回滚策略

- calorieEstimate.js / metEstimate.js **文件不删除**，仅加 deprecate 注释。若毕设中期需要恢复"热量"展示，只需：
  1. day.vue 恢复 kcal 累计 import 与 props 传参；
  2. HeartRateToggle/Popup 恢复 kcal stat DOM；
  3. strengthTrainingAnalyzer 结果可不删除（并行展示）。
- TrainingAnalysisCard 组件为新增，移除不影响其他功能。

### 8.3 风险点与保护

| 风险 | 保护措施 |
|---|---|
| HR 窗口 estimated duration 经常为 0（用户改组间歇与实际不一致） | estimated=0 时 `hr.analyzed=false`，不强行取 0 秒窗口；`⚠ HR 窗口长度异常，跳过` |
| restingHR 未填 + 训练初期采样也不足 | restingHR fallback 返回 0.4×maxHR，cardiovascularLoad 顶部用小字 `(估算 restingHR=xx, 建议在身体档案填写)` |
| 用户同一天多段训练（离开后再回来） | **本期 MVP 合并为单段**：若用户在 finalized 后追加组，status 重置为 in_progress，并取「首个 entry ts → 最新 entry ts」作为 session 范围（论文 limitation 章节声明：单段假设避免 session split 复杂度；跨日训练天然分离）。未来展望：升级为 `trainingAnalysisSessions: []` 多段数组 + Tab1 顶部切换器 |
| Epley 估算 e1RM 为 0（历史最佳全为 bodyweight 0kg） | relativeIntensity.value=null，UI 显示 "—"，不做 0 除法 |
| profile.age = 0（用户在身体档案中未填生日/年龄） | maxHR 无法用 220-age 得出，保护：`session.cardiovascularLoad = null` 并在 restingHrUsed.maxHrUsed 处标注 `value: null, source: 'age-missing'`；set 级 HR 统计不依赖 maxHR 依然可用 |
| profile.weight = 0 | 不影响分析（Mechanical/Cardiovascular 均不依赖体重参数），但 Epley 若遇到 bodyweight（bwMode）条目 weight=0 时跳过 e1RM 估算，relativeIntensity=null |

## 9. 单测与验证要点

新增测试文件：`tests/strengthTrainingAnalyzer.test.js`（纯函数无需 uni，node 可跑）。

必测 case：
1. `extractHrWindow + calcHrMetrics`：采样充足（10）= analyzed true 数值正确；采样 2 = analyzed false 全 null。
2. `calcCardiovascularLoad`：2 个采样点梯形积分手工核对；单点 = null；restingHR>=maxHR 保护返回 null。
3. `estimateE1RMEpley + calcRelativeIntensity`：100kg×5 = 116.67 e1RM，相对强度 80kg 对 e1RM = 0.6857 左右。
4. `analyzeTrainingSession`：构造 3 组（含 1 组 timestamp=null）+ 100 个 HR 样本 → 断言：
   - setAnalyses 长度 3，其中 1 组 HR analyzed=false；
   - mechanicalLoad 手工求和匹配；
   - cardiovascularLoad 非 null；
   - actionAnalyses.卧推.analyzedSetCount ≤ 总组数。
5. transitionTime 边界：最后一组 transition=null，estimatedSetDuration=null。
6. 边界：entries 空 → 返回 0/null/安全值，不崩。
7. `estimateRestingHr` 三分支：
   - 初始 60s ≥10 个采样 → value=最小HR，source='window'
   - 初始 60s 不足 10 个采样 + fallbackAge 有效 → value=round(maxHR×0.4) source='formula'
   - 两者都不满足 → value=null source='none'
8. `profile.age === 0` 时调用 analyzeTrainingSession → maxHrUsed.value=null, source='age-missing'，cardiovascularLoad=null；set 级 hr 指标仍正常分析。

集成验证（真机/模拟器）：
- 连接心率手环，做 2-3 动作 3×3 组训练，保存组时间戳按实际节奏 > 30s apart；
- 训练结束前后查看 TrainingAnalysisCard 卡片的双指标；
- 跳转到独立页 Tab1/2/3 依次正常渲染、不白屏、无异常日志；
- 历史数据（旧格式 dayData）打开不报错，显示兼容提示。
