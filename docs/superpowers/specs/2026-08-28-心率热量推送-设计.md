## 1. 概述与目标

在现有 FitNote 健身记录小程序基础上，新增一组围绕"训练心率"的能力，补齐毕设选题中"设备传感器调用（蓝牙）"与"消息推送机制"两个核心缺口：

1. **蓝牙心率接入**：连接用户的蓝牙手环（开启心率广播，标准 HRS 协议），在训练页实时显示心率。
2. **热量估算**：用心率 + 身体数据（年龄/性别/体重）+ 训练时长，按 Keytel 公式估算本次训练消耗热量。
3. **身体数据档案**：新增用户身体数据存储，作为热量估算与心率档位计算的基础。
4. **消息推送**：训练日定时提醒 + 组间休息到点通知。

**成果形式**：完整前端源码（融入现有 FitNote），无需独立后台管理系统。

## 2. 功能范围（方案 A 精简版）

- 训练页实时心率展示 + 本次消耗热量累计
- 训练结束写入当日记录（平均心率 / 总消耗 / 时长）
- 统计页新增"消耗热量趋势"
- 训练日提醒推送 + 组间休息到点推送

**不在本次范围（方案 B 内容，列为论文未来展望）**：整段心率时序存储、心率区间分布饼图、心率趋势折线。

## 5. 蓝牙心率接入设计

### 5.1 协议

标准蓝牙心率服务（HRS）：
- 服务 UUID：`0x180D`（`0000180D-0000-1000-8000-00805F9B34FB`）
- 心率测量特征 UUID：`0x2A37`，需 `notifyBLECharacteristicValueChange` 订阅
- 数据解析：flags 字节（第 0 字节 bit0 决定心率值是 uint8 还是 uint16），心率值在后续 1-2 字节。本设计按 uint8 解析（绝大多数手环），flags bit0=1 时切 uint16。

### 5.2 连接生命周期

- **进入训练页**：若缓存有 `lastHrDeviceId`，自动 `createBLEConnection`；失败则进入"未连接"态，用户可点心率圆触发扫描。
- **扫描选择**：`startBluetoothDevicesDiscovery` + 过滤含 `0x180D` 服务 → 列表展示设备名/RSSI → 选中后 `createBLEConnection` + 订阅 `0x2A37` → 缓存 `lastHrDeviceId`。
- **断线重连**：`onBLEConnectionStateChange` 监听断开 → 自动重连最多 3 次（间隔 1.5s），仍失败则心率圆显示"未连接"，不阻断训练。
- **退出训练页**：`onUnload/beforeUnmount` 调 `closeBLEConnection` + `stopBluetoothDevicesDiscovery`，省电。
- **App 后台**：训练页 `onHide` 不主动断开（允许后台继续收心率用于累计），`onShow` 恢复；仅在 `onUnload` 断开。

### 5.3 适配器与权限

- `uni.openBluetoothAdapter` 初始化，失败提示用户开启蓝牙。
- Android 权限：`manifest.json` 增加蓝牙权限（已配 location 用于备份，需补蓝牙相关）。
- iOS/小程序：用户首次使用触发系统授权弹窗。

### 5.4 抽象接口（bleHeartRate.js）

```
initAdapter()                          → Promise<boolean>        初始化蓝牙适配器
startScan(onFound: (dev) => void)      → 扫描，回调每台设备
stopScan()
connect(deviceId)                      → Promise<{hr:number}>    连接并订阅，resolve 首次心率
disconnect(deviceId?)
onHeartRate(cb: (hr:number) => void)   → 注册实时心率回调
onStateChange(cb: (state:string) => void)  状态：disconnected/connecting/connected/reconnecting
getLastDeviceId(): string|null
```

状态机：`disconnected → connecting → connected →（断线）→ reconnecting → connected / disconnected`。

## 6. 身体数据档案（stores/userProfile.js）

**Storage Key**：`fitness_user_profile`

**State**：
```js
{
  gender: 'male' | 'female',
  age: number,          // 岁
  height: number,       // cm
  weight: number,       // kg，当前值
  weightHistory: [{date, weight}],  // 可选历史，用于 BMI 趋势
  updatedAt: string
}
```

**Actions**：`load` / `save` / `updateProfile(patch)` / `getMaxHeartRate()`（= 220 − age）。

**入口**：`DaySettings` 设置面板新增"身体数据"项，跳转或弹窗填写。体重变化时可选记入 `weightHistory`。

**校验**：age 5-100、height 100-250、weight 20-300；缺失时热量估算返回 0 并提示补全档案。

## 7. 热量估算算法（utils/calorieEstimate.js）

采用 Keytel 公式（基于心率，学术界认可，无需最大心率）：

```
男 kcal/min = (-55.0969 + 0.6309×HR + 0.1988×age + 0.2017×weightKg) / 4.184
女 kcal/min = (-20.4022 + 0.4472×HR - 0.1263×age + 0.074×weightKg) / 4.184
```

**导出函数**：
```
calcKcalPerMin(hr, {gender, age, weight}) → number  单分钟消耗（截断负数=0）
calcSessionKcal(samples, profile)         → number  按心率采样序列（[{hr, durMin}]）累计
estimateAvgHr(samples)                    → number  平均心率
```

**累计策略**：训练中每分钟取该分钟心率均值（或最近一次心率），调 `calcKcalPerMin` 累加；心率断连期间不计入时长与热量。

## 8. 心率档位定义（utils/heartRateZones.js）

最大心率 `maxHR = 220 − age`。5 档（按 maxHR 百分比）：

| 档位 | 区间 | 颜色 | 状态标签 |
|---|---|---|---|
| 热身 | 50-60% | 蓝 #3b82f6 | 热身 |
| 燃脂 | 60-70% | 绿 #22c55e | 燃脂 |
| 有氧 | 70-80% | 黄 #eab308 | 有氧 |
| 无氧 | 80-90% | 橙 #f97316 | 无氧 |
| 极限 | 90-100% | 红 #ef4444 | 极限 |

**导出**：`getZone(hr, age)` → `{index, label, color, rangeText}`；`getZones(age)` → 5 档完整定义（供区间条渲染）。

低于 50% 不高亮任何档（静息/未运动）；UI 区间条当前档满色高亮，其余 0.45 透明度。

## 9. UI 交互设计（components/HeartRateToggle.vue）

复用现有底部 `save-row` 区域，在计时按钮左侧加心率圆按钮。

### 9.1 三态

- **未连接态**：心率圆显示 `♥-`（灰色边框），点击触发扫描连接。
- **收起态**：心率圆显示 `♥142`（红边框圆形，52×52，border-radius 50%），与计时/设置按钮并排。
- **展开态**：点击心率圆 → 圆形向右扩展为铺满底部的圆角矩形 tag（width 52→300，border-radius 50%→14px，280ms 缓动），计时/设置按钮 width→0 + opacity→0 隐藏；tag 内容：`♥142 bpm` | 压缩区间条 + 当前档位状态（如"无氧"） | `🔥326 kcal` / 下方小字 `24:15`。
- 再次点击 tag → 收起回圆形，计时/设置恢复。

### 9.2 props / emits

```
props:
  hr: number|null          当前心率
  kcalTotal: number        累计消耗
  durationSec: number      训练时长
  zone: {label,color}      当前档位
  zones: Zone[]            5 档定义
  connected: boolean
emits:
  toggle-connect           点击未连接圆，触发扫描连接
  request-settings         打开设备管理（长按心率圆）
```

### 9.3 渲染要求

- 区间条压缩：5 段，每段宽 9px、高 7px、gap 2px。
- 当前档状态文字用该档颜色。
- 动画用 `transform/width/opacity`，≤300ms，遵守 `prefers-reduced-motion`。
- 深色模式适配（沿用现有 Design Token）。

## 12. 错误处理

| 场景 | 处理 |
|---|---|
| 蓝牙适配器初始化失败 | 心率圆显示"未连接"，提示开启蓝牙，不阻断训练录入 |
| 连接/订阅失败 | 重连 3 次后回退"未连接"，保留上次累计热量 |
| 心率数据异常（0/负/>220） | 丢弃该次采样，不计入热量与平均 |
| 身体档案缺失 | 热量估算返回 0，心率圆展开态提示"请补全身体数据" |
| 订阅消息被拒 | 静默降级，功能不受影响 |
| 设备不支持蓝牙 | 检测 `uni.openBluetoothAdapter` 失败，隐藏心率圆入口（设置中可手动开启） |

1. 训练页能扫描并连接支持 HRS 的手环，实时显示心率（误差 ≤2s）。
